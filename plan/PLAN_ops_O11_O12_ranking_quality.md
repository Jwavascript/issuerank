# O11·O12 랭킹 품질 개선 1차

2026-11-17 사용자 승인: 검색 판정 근거 기록 → 전체 출처 2→4페이지 → AI 같은 사건 판정. 운영 `ex12/`에서 순차 계획·제작·심사. 직전 수집 계획 O9a를 보존한다.

## 이번 범위
- SPEC US01·02·03, AC01-1·2·5, AC02-1·2·3, AC03-1·2. 핵심은 단독 후보가 많은 표본을 확대하고 연관기사 추정의 근거를 확인 가능하게 만드는 것.
- 기본 top1+전체4(옵션0~4), 수집 최대30회 + 검색 최대36회 = 뉴스 최대66회/실행. 호출마다 첫 호출부터 31초 대기하여 단계 경계에서도 15분30회 이하. 같은 키의 다른 수동 실행과는 겹치지 않도록 운영한다. daily timeout 60분(뉴스 대기 최대34.1분 + AI·빌드 준비 여유).
- 검색 결과 1페이지의 제목·API설명문(300자)·링크·출처·시각만 보관. 본문·키·응답 원문은 보관하지 않음. 후보별 원 totalResults, 페이지 수, 낱말 판정 수, AI 판정 수/실패 사유, 적용 방식, 최종 추정 수를 `.data/ranking-quality/YYYY-MM-DD.json`에 저장. Actions artifact 14일 보관. 공개 API·DB 스키마 변경 없음.
- AI는 기존 Responses SDK·MODEL 유지, 사건 묶음 제목·설명문120자와 검색 첫 페이지(최대10건)를 비교하여 기사별 boolean 반환. 주체·행동·대상·시점이 같은 사건만 인정, 동일 주제·기관만으로 인정하지 않음. 페이지 전체 결과를 분모로 하며 빈/잘못된 제목은 불일치. 빈 결과면 AI 요청0. 반환 길이·형식 불일치/거절/실패는 낱말 규칙 대체, 로그·종료1로 알림. `--ai 0`은 기존 규칙 유지.
- 산식 D13의 max(round(totalResults×관련비율), 수집묶음크기)는 유지하되 AI 성공 시 관련비율을 AI 판정으로 대체. 여전히 추정치이며 실제 목록 개수로 표현하지 않는다. 대표·북마크 보호·순위 동점 기준·요약 실패 문구 유지.
- 추가 AI 최대36회, 각 출력1500토큰, 자동 재시도0. 기존 정리2회·요약최대30회 유지. 비용 실측은 운영 후; 숫자가 커져야 통과하는 기준을 쓰지 않는다.
- 새 패키지 없음. 외부 키는 기존 ex12/.env의 NEWSDATA_API_KEY·OPENAI_API_KEY·DATABASE_URL. 값 출력 금지.
- artifact는 공식 `actions/upload-artifact@v7`을 사용하며 명시한 JSON 경로에만 include-hidden-files=true 적용(.data 경로 제외 방지), 다른 숨김파일 업로드 금지. 기준 묶음 제목·설명문120자·크기도 진단에 포함. 하루 총3회(최대198요청), 자동2회가 있었으면 수동1회까지이며 다른 점검 호출이 있으면 실제 잔액 우선.
- 하지 않음: O11 후속 기사 목록 화면/요약 재사용/언론사 표시, O12 후속 낮·저녁 실행, O10 사건 재병합, 실제 DB 재수집·삭제, 커밋·푸시·배포.
