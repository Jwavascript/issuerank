# 다음 버전 기능 제안 — 관심 키워드 타임라인

2026-11-15 · 사용자 아이디어를 구체화한 **검토 초안**. 구현 승인이나 확정 PLAN이 아니다. 기존 D37~D39와 운영 개선 순서를 변경하지 않는다.

후속(같은 날): 사용자가 이 초안을 바탕으로 계획→빌드→검증을 요청했다. 실제 구현 기준은 `PLAN_ops_O14_keyword_timeline.md`·D40이며 아래 내용은 최초 제안 기록으로 보존한다. 의미가 모호한 사건 연결은 보류하고 기존 기사 묶음·URL/동일 보도 근거로 시작한다.

## 1. 기능의 목적

**관심 있는 기업·인물·주제에 무슨 일이 있었고, 무엇이 새로 달라졌는지 한 화면에서 따라본다.**

현재 이슈랭크의 “어제 많이 보도된 사건”에 “내 관심 주제의 흐름”을 더한다. 기사 목록을 계속 쌓기보다 중요한 사건과 후속 전개를 골라 보여준다.

주 사용자 상황:
- 면접 전 특정 기업의 최근 한 달 주요 뉴스를 몰아서 확인한다.
- 업무와 관련된 산업·정책을 저장하고 새 전개가 생겼을 때 확인한다.
- 두 기업 또는 서로 관련된 주제를 같은 시간축에서 비교한다.

## 2. 사용자 흐름

1. 검색에서 `삼성전자`처럼 관심 키워드를 입력한다.
2. 최근 30일의 주요 보도를 시간순으로 본다. 7일·30일·90일 또는 직접 기간을 선택한다. 저장된 기간 안에서만 결과를 제공한다.
3. `관심 키워드 저장`을 누르면 다음에도 바로 열 수 있다. 저장과 기기 간 동기화는 로그인 후 제공하는 안이다. 검색·열람은 로그인 없이 가능하다.
4. `SK하이닉스` 등을 추가하면 같은 날짜 축에 두 키워드의 사건을 함께 표시한다.
5. 관심 키워드별 알림을 켜면 새로운 주요 전개를 다음 아침 알림에서 확인한다.

위 키워드는 사용 흐름 설명용이며 실제 뉴스 결과를 뜻하지 않는다.

## 3. 화면과 동작

| 영역 | 제안 동작 |
|---|---|
| 검색창 | 기업·인물·정책·산업 키워드 검색. 예: 삼성전자, 기준금리, 반도체 |
| 관심 키워드 | 이름과 고정 색상으로 표시. 저장 최대 5개·동시 비교 최대 3개로 시작하는 안. 숫자는 확정 전 |
| 기간 | 기본 최근 30일. 검색 가능한 저장 기간과 마지막 갱신 시각 표시 |
| 보기 | 기본 `주요 변화`, 필요하면 `관련 보도 더 보기`로 접힌 결과 확인 |
| 타임라인 | 왼쪽에 날짜·세로선·사건 점, 오른쪽에 사건 카드. 최신이 위이며 아래로 내려가면 과거. 배경부터 볼 때는 `오래된 순` 선택 |
| 사건 카드 | 짧은 제목·핵심 내용·선정 이유·키워드 이름·출처·보도 시각·원문 링크. 요약 실패 시 기존 “요약 없음 · 원문을 확인해 주세요” 유지 |
| 이어지는 사건 | 새 전개 카드에서 `이전 흐름 보기`로 앞선 사건 연결. 사실 확인이 어려운 연결은 만들지 않음 |
| 작은 화면 | 날짜 축 하나와 카드 한 열. 키워드별 가로 칸을 늘리지 않아 세로 스크롤로 읽게 함 |

타임라인의 기본 날짜는 **대표 기사의 발행일(KST)**이다. 기존 랭킹 날짜는 수집한 날이므로 그대로 가져다 쓰지 않는다. 실제 사건 발생일을 확인하지 못했으면 보도일을 사건 발생일로 표현하지 않는다. 갱신 시각은 별도로 표시한다.

## 4. 여러 키워드를 함께 보는 규칙

- 기본은 선택한 키워드 **중 하나라도 관련된 사건**을 모두 표시한다. 모든 키워드의 동시 언급을 요구하지 않는다.
- 키워드마다 색상을 고정한다. 선택을 켜고 꺼도 다른 키워드의 색상은 바뀌지 않는다.
- 색상과 함께 키워드 이름을 항상 표시해 색 구분이 어려워도 읽을 수 있게 한다.
- 하나의 사건이 두 키워드에 걸리면 **카드 하나에 두 키워드 표시**를 붙인다. 키워드마다 같은 카드를 반복하지 않는다.
- 키워드별 표시를 잠깐 끄고 켜며 비교한다. 이는 저장된 키워드 삭제나 알림 끄기와 구분한다.
- 같은 날짜의 공통 사건은 관련성을 보여줄 뿐, 두 주제 사이의 인과관계라고 해석하거나 표시하지 않는다.

## 5. “중요한 것만” 보여주는 방법

관련성 → 중복 정리 → 새 전개 확인 → 주요 항목 선정 순서로 처리한다.

| 판단 | 제안 기준 |
|---|---|
| 키워드 관련성 | 제목·저장된 API 설명문·이슈 제목에서 확인. 비슷한 글자가 있다는 이유만으로 같은 대상이라 판단하지 않음 |
| 반복 보도 | 같은 사건을 여러 언론사가 보도한 경우 카드 하나로 묶고 출처 목록으로 접음 |
| 새로운 전개 | 발표→확정, 조사→처분, 출시 계획→실제 출시처럼 사실관계가 달라진 경우 별도 시점으로 표시 |
| 주요 보도 | 관련성이 확인된 사건 중 보도 규모와 사건 영향을 함께 보고 선정. 다수 출처 보도, 공식 결정·실적 발표·제도 시행 등이 후보 |
| 표시량 | 기본 키워드별 하루 최대 3개 주요 항목을 제안. 공통 사건은 한 번만 표시하며, 기준 미달 항목으로 칸을 채우지 않음 |
| 선정 이유 | `여러 매체 보도`, `정책 확정`, `후속 발표`처럼 근거를 짧게 표시. 근거를 확인할 수 없으면 해당 설명을 붙이지 않음 |

보도량이 많다는 것과 개인에게 중요하다는 것은 다르다. 기존 AI importance는 “한국 독자 전체에 미치는 영향”이므로 개인 관심도를 대신하는 기준으로 쓰지 않는다. 표시명은 객관적 중요도를 보장하는 표현보다 `주요 변화`로 제안한다.

날짜를 넘어 같은 사건을 연결하는 기능이 필요하다. 기존 issues.id는 날짜별 식별자여서, 제목을 단순히 비교하거나 기존 ID를 재사용하는 것만으로는 부족하다. 별도의 연결 정보로 기존 이슈·북마크를 보존하는 방향을 제안한다. 모호한 항목은 독립 카드로 두고 연결 판정을 보류한다.

현재 연관기사 수는 최근 48시간 검색을 검증해 추정한 값이다. 날짜 사이에 기사 범위가 겹치므로 **일별 수를 더해 누적 보도량이라 표시하거나, 그 차이만으로 보도 급증을 알리지 않는다.**

검색 별칭은 명시적으로 확인된 표현부터 지원한다. 회사명과 그룹명, 약칭과 동명이인을 자동으로 같다고 처리하지 않는다. 임의의 의미 확장·자동 동의어 추정은 첫 버전에서 미룬다.

## 6. 키워드 알림

| 항목 | 제안 |
|---|---|
| 시점 | 아침 수집·정리 완료 후 기존 아침 알림 시간대에 발송 |
| 조건 | 등록 이후 처음 확인된 주요 사건 또는 이미 보던 사건의 확인된 새 전개 |
| 제외 | 같은 내용의 재보도, 새 변화가 없는 반복 기사, 단순 기사 수 증가 |
| 등록 직후 | 과거 검색 결과를 한꺼번에 알리지 않음. 기존 결과는 시작 기준으로 사용 |
| 횟수 | 기기별 하루 최대 1통으로 묶는 안. 여러 키워드에 걸린 사건도 한 번만 집계 |
| 기존 아침 알림 | 둘 다 켰으면 한 통으로 합치는 안. 일반 아침 알림만 켠 사용자는 기존 기능 유지 |
| 내용 | 예: `관심 키워드에 새로운 주요 소식 3건` + 대표 키워드. 예시이며 실제 발송 내용 아님 |
| 누르면 | 해당 키워드·기간이 선택된 타임라인으로 이동하고 새 항목 표시 |
| 끄기 | 키워드별 알림과 전체 알림을 각각 끌 수 있음. 저장·열람은 계속 가능 |
| 실패·지연 | 수집 실패를 “관련 소식 없음”으로 처리하지 않음. 기존 발송 제한 시각을 넘겨 임의로 늦은 푸시를 보내지 않음 |

현재 웹 푸시는 로그인 없는 기기별 구독이며, Android v1에는 앱 자체 알림이 없다. 관심 키워드의 계정 저장과 기기별 알림 연결은 새 설계가 필요하다. **웹에서 먼저 검증하고 Android 열람·알림을 별도 단계로 확장**하는 안을 제안한다. 기존 푸시가 계정별 기능을 이미 지원한다고 가정하지 않는다.

알림 재시도·누락 처리·계정 전환 시 기기 연결 해제 규칙은 발송 구현 PLAN에서 확정한다.

## 7. 현재 데이터로 가능한 범위와 한계

- 기존 DB에는 날짜별 이슈 후보와 수집 기사(제목·설명문·발행 시각·출처·이슈 연결)가 있다. 첫 검색은 일별 Top 5에만 한정하지 않고 저장된 후보 전체에서 찾는 방향이다.
- 검색·페이지 이동마다 newsdata나 OpenAI를 부르지 않고 저장된 자료를 조회한다. 공통 키워드의 처리 결과도 재사용하는 방향이다.
- **일반 뉴스 검색처럼 모든 기사를 찾는 서비스는 아니다.** 현재 수집은 섹션별 일부 표본이므로 특정 기업이나 작은 주제의 소식을 놓칠 수 있다. 화면에 `이슈랭크가 수집한 뉴스에서 검색합니다`를 표시한다.
- 검색 결과 없음, 주요 변화 없음, 해당 기간 수집 실패를 서로 다르게 안내한다. 저장 시작일 이전의 결과를 제공하는 것처럼 표시하지 않는다.
- NewsData 공식 문서의 무료 플랜은 12시간 지연·최근 48시간 접근이다. 저장해 온 기간의 검색은 가능하지만, 수집하지 않은 과거 기간의 복원이나 즉시 속보 알림은 현재 방식으로 보장할 수 없다.
- 키워드 전용 수집을 추가하면 누락을 줄일 수 있으나 호출 예산과 기존 수집에 영향을 준다. 첫 검증 결과를 보고 별도 결정한다. API 상품·모델·요금제를 이번 초안에서 변경하지 않는다.
- 타임라인 연결·새 전개 판정은 현재 없는 기능이다. 공통 처리로 묶더라도 추가 개발·AI 처리 비용은 발생할 수 있어 실제 비용을 측정한 뒤 한도를 정한다. 비용 0을 보장하지 않는다.
- 기사 본문 저장·표시는 추가하지 않는다. `정보`의 첫 범위는 뉴스와 그 근거가 있는 요약이다. 공시·통계·주가·커뮤니티는 후속 검토한다.

공식 확인(2026-11-15): [NewsData API 문서](https://newsdata.io/documentation). 저장 상태는 코드 구조를 확인했으며 실제 운영 DB의 기간·건수·키워드별 검색 품질은 이번에 조회하지 않았다.

## 8. 권장 개발 순서

| 단계 | 결과물 | 다음 단계로 넘어가는 기준 |
|---|---|---|
| 1. 저장 뉴스 검색 | 단일 키워드·기간 검색과 보도일 기준 단순 타임라인. 관련 보도와 출처 확인 | 실제 관심 키워드에서 충분한 결과가 나오는지 확인. 부족하면 수집 범위를 먼저 결정 |
| 2. 주요 변화 타임라인 | 여러 키워드 색상 비교·공통 사건 합치기·날짜를 넘는 흐름 연결·반복 보도 접기 | 사람이 확인한 사례에서 새 전개를 숨기거나 다른 사건을 잘못 합치지 않는지 검증 |
| 3. 저장과 아침 알림 | 계정별 관심 키워드·기기 연결·새 변화 알림 | 등록 직후 과거 알림 없음·중복 발송 없음·끄기·실패 처리·계정 전환 검증 |
| 4. 확장 | Android 동일 화면·앱 알림, 주간 정리, 키워드 전용 수집 등 | 사용성과 비용을 확인한 항목부터 별도 승인 |

1~3을 다음 버전의 전체 목표로 묶되, 1단계의 데이터 적합성을 먼저 검증한다. 기존 운영 개선 O10~O13의 제목 품질·검색 결과 재사용·수집 범위 개선이 이 기능의 기반이 된다. 착수 순서는 사용자와 확정한다.

## 9. 구현 PLAN 전에 확정할 사항

1. **우선 사용자:** 기업·산업을 따라보는 직장인과 면접 준비생을 첫 대상으로 제안. 이에 맞춰 회사·산업 키워드로 검증한다.
2. **첫 지원 화면:** 웹 우선, Android는 검증된 동작을 다음 단계에서 적용하는 안.
3. **알림 기대:** 실시간 대신 아침 주요 변화 알림으로 시작하는 안.
4. **검색 범위:** 저장된 뉴스에서 시작하되, 표본 부족이 확인되면 키워드 전용 수집 여부와 호출 예산을 결정한다.
5. **표시 기준·한도:** 주요 변화 선정 규칙, 저장 5개·동시 비교 3개·하루 주요 항목 3개는 검증용 제안이며 확정값이 아니다.

현재 SPEC의 승인된 US·AC에는 이번 기능이 없다. 위 범위를 정한 뒤 SPEC에 사용자 스토리와 인수 기준을 추가하고, 해당 운영 PLAN에서 API·입력 규칙·데이터 저장·실행 예산·검증표를 확정한다. 이번은 기획만 수행하며 제작·심사 PASS를 선언하지 않는다.

## 10. 검증할 핵심 사례

- 같은 키워드라도 서로 다른 기업·인물의 기사이면 섞지 않는다.
- 같은 사건의 언론사별 보도는 한 카드로 모이고 원문 출처를 열 수 있다.
- 같은 주제의 다음 날 새 결정은 숨기지 않고 앞선 흐름과 연결한다.
- 두 키워드의 공통 사건은 카드 하나·키워드 이름 두 개로 나타난다.
- 오래된 순·최신순, 기간 변경, 추가 페이지 조회에서 누락·중복이 없다.
- 요약 실패·수집 실패·검색 결과 없음의 안내가 구분된다.
- 관심 키워드를 저장해도 과거 사건 알림이 쏟아지지 않는다.
- 반복 실행·공통 키워드·기존 아침 알림 때문에 알림이 중복되지 않는다.
- 키워드 관련성을 엄격하게 고르되 소규모 분야의 실제 주요 전개가 일괄 탈락하지 않는지 사람이 확인한다.

위 사례는 향후 검증 기준 제안이다. 이번에 제품 시험·운영 호출을 실행한 결과가 아니다.
