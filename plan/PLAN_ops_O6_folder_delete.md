# PLAN_ops_O6_folder_delete — 북마크 폴더 삭제

> 이유: 북마크 폴더는 만들 수만 있고 지울 수 없다(`server/routes/folders.ts` = GET · POST뿐, 화면에도 버튼 없음) → 다 본 주제 · 잘못 만든 폴더가 칩 줄에 계속 쌓인다(사용자 요청 2026-10-20 "기존의 북마크 폴더를 삭제하는 기능이 없어"). 그래서 북마크 화면에서 폴더 칩을 고르면 칩 줄 끝에 `폴더 삭제`를 보이고, 확인 창에 함께 지워질 북마크 수를 보여 준 뒤 확인하면 그 폴더와 안의 북마크를 서버에서 지운다.

## API — `DELETE /api/folders/{folderId}` (D31)
| 항목 | 규칙 |
|---|---|
| 순서 | 세션 → id 형식 → 저장소 `deleteFolder(userId, folderId)` → 응답. 세션은 기존 북마크 · 폴더 미들웨어(`server/app.ts`)가 그대로 처리: 쿠키 없음 · 변조 · 만료면 401 `{ "message": "로그인이 필요합니다" }`, 형식 검사 · 저장소 접근보다 먼저 |
| id 형식 | `f` + 숫자 1~9자리(메모리 샘플 `f1`~`f3`) 또는 `f` + 소문자 UUID(새 폴더 `f${randomUUID()}`) — 정확한 식은 표 아래. 근거: 0006은 folders · bookmarks가 비었을 때만 적용됐고(파일 안 빈 표 검사) 그 뒤 폴더는 모두 `createFolder`가 만듦 → 실제 DB에 다른 꼴 없음(검증 5 시작에서 형식 밖 행 수 = 0 확인). 틀리면 400 `{ "message": "요청 형식이 올바르지 않습니다" }`(기존 BAD_REQUEST) · 저장소 호출 0 |
| 없음 · 남의 것 | 둘 다 404 `{ "message": "폴더를 찾을 수 없습니다" }`(POST /api/bookmarks의 폴더 없음과 같은 문구) — 상태 · 본문 · 머리가 같아 다른 사용자 폴더가 있는지 드러내지 않음 |
| 성공 | **204**(본문 없음). 고른 이유: ① 기존 DELETE 둘(북마크 해제 · 알림 끄기)이 204 → 계약 · 테스트 · 화면 `api()`(204면 본문을 읽지 않음) 처리가 같음 ② 화면은 성공 뒤 `GET /api/bookmarks` · `/api/folders`를 다시 받아 실제 상태를 그림 → 지운 수를 쓸 곳이 없음 ③ 토스트에 수를 쓰지 않아, 창이 열린 사이 다른 기기에서 더한 북마크로 수가 달라져도 틀린 문구 0. 200 `{ deletedBookmarks }`는 고르지 않음 |
| 지우기(DB) | `server/db/store.ts` dbStore, `db.transaction` 하나: ① `folders`에서 `id = folderId AND user_id = userId` 행을 `FOR UPDATE`로 잠가 읽음 — 없으면 false(404 · 쓰기 0) ② `bookmarks`에서 `user_id = userId AND folder_id = folderId` 삭제 ③ 그 `folders` 행 삭제 → true. 잠그는 이유: 그사이 다른 기기의 북마크 저장이 끼어도 지우기가 FK 오류로 실패하지 않음(그 저장 쪽이 기다렸다 실패 — 확인 필요 3). 중간 실패 = 모두 되돌림(폴더 · 북마크 그대로) · 다른 사용자 행 영향 0(조건에 user_id + 복합 FK가 같은 사용자 북마크만 허용) · issues · articles · 요약 · 계정 · push_subscriptions 쓰기 0 |
| 지우기(메모리) | `server/sample.ts` memoryStore(테스트 · 개발용): 그 사용자 · 그 id 폴더가 없으면 false, 있으면 그 사용자 · 그 폴더 북마크 → 폴더를 지우고 true(DB와 같은 결과) |
| 응답 · 보호 | 모든 응답 `Cache-Control: no-store`(기존 미들웨어 + BFF 개인 경로 — 북마크 · 폴더와 같음) · 로그 = 기존 안전 코드뿐. **Origin 검사는 더하지 않음** = 지금 `DELETE /api/bookmarks/{issueId}`와 같은 꼴: 세션 쿠키가 `SameSite=Lax` · HttpOnly(Better Auth 기본, https면 `__Secure-`)라 다른 사이트의 fetch에는 쿠키가 실리지 않고, DELETE는 CORS 사전 요청이 필요한데 허용 머리가 없어 보내지지도 않음. 그 밖 메서드(GET `/api/folders/{id}`) · id 없음(`DELETE /api/folders`) · 경로 더 붙음(`/api/folders/f1/x`) = Hono 기본 404(지금과 같음) |
| 계약 | `openapi.yaml` 새 경로 `/api/folders/{folderId}` delete: `operationId: deleteFolder` · sessionCookie · 경로 칸 `pattern` = 아래 식 · 204(본문 없음) · 400 · 401(LoginRequired) · 404(예시 문구 = 위와 같음). `info.version` 0.5.0 → 0.6.0. 그 밖 경로 · 스키마 글자 그대로 |
- id 형식 식(서버 `server/schemas.ts` 한 곳 · openapi pattern 같은 값): `^f(?:[0-9]{1,9}|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})$`

### 사용자 확인 (마지막에 한 번에 하는 목록에 넣을 문장)
- 휴대폰(Chrome 또는 설치한 이슈랭크 앱)에서 로그인 → 북마크 → 지워도 되는 폴더 칩을 누르면 칩 줄 오른쪽 끝에 `폴더 삭제`가 보이고 `전체`를 누르면 사라지는지 → 다시 그 폴더 → `폴더 삭제` → 창의 "북마크 n개도 함께 삭제됩니다"의 n이 칩 숫자와 같은지 → `취소`(바뀐 것 없음) → 다시 `폴더 삭제` → `삭제` → `‘이름’ 폴더를 삭제했습니다` 토스트 · `전체` 보기 · 그 폴더 칩과 안의 북마크가 사라짐(캡처). (선택) PC에서 새로 고쳐도 같은지. 지울 폴더가 없으면 새 폴더를 만들어 북마크 1개를 넣은 뒤 지워 보기.

- 확인 필요(추천안으로 진행 — 멈추지 않음):
  1. 폴더 id 형식 400 규칙: 실제 DB에 형식 밖 id가 없다는 근거 = 0006이 빈 표에서만 적용 + 그 뒤 모두 `createFolder`(`f${randomUUID()}`) → 검증 5 시작에서 0 확인. 0이 아니면 제작은 그 수만 보고하고 멈춤(규칙을 넓힐지 사용자 결정).
  2. `/privacy` 3항("계정 정보 · 북마크 · 폴더는 삭제 요청을 처리할 때까지 보관") — 이번엔 그대로: 북마크 해제처럼 사용자가 직접 지우는 동작이고 새로 모으는 정보 0이며, 문안을 바꾸면 시행일 · 변경 줄도 바뀌는데 기존 push-ui 테스트가 12항을 글자 그대로 고정. "직접 지우거나 …"로 다듬을지는 다음 문안 확인(O2 21 · O5 24) 때 후보.
  3. 같은 계정 두 기기: 창이 열린 사이 다른 기기에서 그 폴더에 저장한 북마크도 함께 지워짐(창의 수보다 많을 수 있음 — 토스트에 수 없음) · 지우는 순간 다른 기기의 저장은 잠금을 기다린 뒤 FK 오류로 500. 드물어 이번엔 기록만.
  4. 실제 글꼴(Pretendard — 이 기기 CDP는 막혀 대체 글꼴)에서 칩 줄 끝 버튼 폭 · 가로 맞춤 → 10번 캡처. iPhone(바깥 누름 · 초점)은 기기 없음 → 다음 iPhone 확인 때 함께.
