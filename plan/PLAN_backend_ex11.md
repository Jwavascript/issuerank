# PLAN_backend_ex11 — 계정별 북마크·폴더 저장

> 이유: ex10은 로그인만 구분하고 북마크·폴더는 공용이다. 서버 세션을 기준으로 본인 데이터만 읽고 쓰도록 완성한다.
> 코드 폴더: `ex11/` (`ex10/` 복사, 이미 있으면 재복사 없음). ex10 PASS 출발, ex08 품질 FAIL·ex09 자동화는 계속 보류.
> SPEC 근거: US-07 · US-08 · US-10 · AC-09-5. D7 날짜별 issueId+폴더, D10 로컬의 독립 브라우저 세션 시연을 적용한다.

## 이번 범위
- Hono 보호 라우트·Store·DB/메모리 저장소에 세션 userId 전달, `0006` 소유권 제약, API401 계약·화면 세션 만료/계정 전환 처리. AI·랭킹·인증 방식·이전 단계 코드는 보존한다.
- 새 패키지: 없음. `ex11/.env`에 기존 DB·인증 설정을 로컬 복사하여 사용하며 새 외부 계정·키 없음.
- 하지 않음: OAuth·계정 연결·이메일 기능·계정 삭제·폴더 이름 변경/삭제/이동/공유·자동화·AI 품질 수정·실제 기사/이슈 삽입·기존 데이터 삭제/임의 귀속.

## 소유권·API 규칙
| 항목 | 규칙 |
|---|---|
| 인증 경계 | `/api/bookmarks`의 GET/POST/DELETE 및 `/api/folders`의 GET/POST는 JSON검사·Store 접근 전에 Better Auth 서버 세션을 검증. 쿠키 없음/만료/변조는 401 `{message:"로그인이 필요합니다"}`. 세션 확인을 생략한 기본사용자/개발 우회 없음. body/query/header의 userId는 신뢰하지 않음. `/api/rankings`와 인증 경로는 기존 공개 범위 유지. |
| 소유권 DB | folders·bookmarks에 `user_id text NOT NULL`과 인증 user.id FK(기본 NO ACTION) 추가. bookmarks 기존 `issue_id` 단독 unique를 `(user_id,issue_id)` unique로 교체, issues FK 유지. folders `(user_id,id)` unique와 bookmarks `(user_id,folder_id)`→folders `(user_id,id)` 복합FK 추가하여 타인폴더 연결을 DB에서도 거절. 기존 단일 folder FK는 보존 가능. 공유DB에 0006 적용 후 이전 ex10의 무소유 쓰기는 호환되지 않으므로 현재 실행은 ex11로 안내(이전코드/DB롤백 없음). RLS활성·공개정책 없음 유지, 서버 소유자 DB접속이므로 애플리케이션 필터는 반드시 별도 적용. |
| 조회 | Store의 북마크·폴더 조회/저장/삭제/생성은 모두 필수 userId 인수. 목록·폴더 count·JOIN에 소유권 적용. GET200: 본인 북마크만 `created_at ↓, id ↓`(동률 안정화), 본인 폴더만 만든 순. 새 계정은 두 목록 `[]`, 다른 계정 데이터로 빈 목록을 채우지 않음. 응답 카드/폴더 칸은 그대로(userId 노출 안 함). 개인 API의 성공·실패 응답은 `Cache-Control:no-store`. |
| 북마크 저장 | POST `{issueId,folderId}`: 유효한 기존 카드/본인폴더만201. 없는/타인폴더404 “폴더를 찾을 수 없습니다”, 없는/Top5 밖 이슈404 “이슈를 찾을 수 없습니다”. 같은 본인 issue 재저장409 “이미 북마크한 이슈입니다”; 다른 본인폴더로 보내도 이동 아님. A와B는 같은 issue 각각저장 가능, 동시 같은계정저장은201하나·409나머지. 과거 날짜도 동일. |
| 북마크 해제 | DELETE `/:issueId`: 본인행만 삭제204, 없거나 타인행만 있으면404 “북마크를 찾을 수 없습니다”. 같은 issue의 다른 사용자행은 보존. |
| 폴더 | POST `{name}`: 기존trim후1~16자·같은이름허용·201 `{id,name,count:0}`. 새 폴더는 요청 세션 소유. 동시생성 충돌을 없애기 위해 신규id는 내장 `randomUUID()` 기반 `f<UUID>` 문자열(기존id보존, ID는불투명문자열). GET count는 본인폴더의 본인북마크만, 빈폴더0. |
| 무소유 기존행 | 2026-10-14 부모 read-only 확인은 folders0/bookmarks0/users0. 적용 직전 다시 확인, 0006이 미적용인 상태에서 folders 또는 bookmarks에 기존행이 있으면 0006만 중단하고 이관결정 질문; 삭제·임의계정귀속·nullable 전환으로 진행 금지. 빈테이블 조건의 마이그레이션은 트랜잭션/쓰기 잠금 하에 확인하여 검사 후 유입도 차단. 0000~0005 재작성·마이그레이션 기록 임의수정 금지. 이미 0006이 적용된 뒤에는 유효한 소유행이 있어도 재실행은 변경0이어야 한다. |
| 화면 세션 | 개인API401이면 현재 세션 상태·목록·폴더필터·선택창 초기화 후 기존 로그인 안내. 로그인/로그아웃/계정변경마다 authVersion 갱신; 이전 계정의 늦은 조회·저장·해제·폴더생성 응답과 되돌리기 callback은 새 계정에 반영/실행하지 않음. 이전 요청의 늦은401도 새 로그인 상태를 지우지 않음. |

## 화면 변경
- 기존 이슈맵·카드·북마크/폴더 선택창·칩·빈 안내 문구 유지. 비로그인 저장은 로그인 안내만, 폴더 생성→즉시저장·해제→되돌리기는 본인 계정에서 기존처럼 동작한다.
- 새 계정 첫 폴더 생성/빈 북마크, 같은 계정의 다른 브라우저 재로그인, A→B 전환에 맞춰 실제 본인 목록만 표시한다. 개인데이터를 localStorage에 보관하지 않는다.

## 검증 방법
- 이전 ex10의 인증·안전실행·쿠키 검증은 유지하되 이번 폴더·명령은 ex11, 기존85개 테스트 기대를 사용자별 계약으로 바꾸고 보완한다. 이전 외부 호출/샘플 삽입 부록은 실행하지 않음. newsdata/OpenAI 요청0, 과거 AI FAIL은 인증/저장 PASS와 별도.
- 안전실행은 ex10 기준 그대로: 대상 ex11/.env만 읽고 stdout+stderr를 캡처하여 URL·인코딩/디코딩 DB비밀번호·API키·인증secret·테스트비밀번호·세션토큰/쿠키 누출검사 false일 때만 결과 출력. DB클라이언트도 try안, 안전 오류코드만, 실제응답/쿠키·인증테이블 원문 출력금지.
- 제작/심사 각각 임시A·B 2계정(총4까지), 각 역할 API/BFF 요청 합계최대250(브라우저자동요청 포함, 뉴스AI0). 실행 전 카운터를 기록하며 실패 후 무분별 반복 금지, 예산 내 원인수정 후 필요한 재검증만. UUID 이메일·폴더이름으로 이번 ID를 즉시기록, existing실제랭킹 Top5이슈2개를 읽어북마크만 생성. 새 기사/이슈/요약/수집기록 삽입금지.
