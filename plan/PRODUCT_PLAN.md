# 이슈랭크 운영 기획안 v1

2026-10-17 작성. 캡스톤 발표(ex01~ex12)를 마치고 실제 운영 서비스로 발전시키기 위한 기획. 기능 단위 구현은 이 문서의 로드맵 순서대로 `agent_prompts/` 계획 → 제작 → 심사로 진행하고, 결정은 PLAN.md 5절, 사용자 스토리는 SPEC.md에 함께 기록한다.

## 1. 목표

- 한 줄 가치: **출근길 1분, 어제 가장 많이 보도된 이슈를 헤드라인으로.** 포털의 "많이 클릭된 기사"가 아니라 "많이 보도된 사건"(연관기사 수) 기준.
- 포지션: 실시간 속보가 아니라 **어제 하루 결산**. newsdata 무료 플랜은 12시간 지연(D3)이라 속보 경쟁은 하지 않는다.
- 북극성 지표(제안): **주 3일 이상 아침(05~10시 KST)에 확인한 사용자 수.** 측정 방법은 O1에서 정한다(개인 식별 없이 위젯 API·사이트 요청 수로 시작).

## 2. 사용자

모두 가설이다. 운영 초기에 주변 5명 이상에게 아래 확인 질문으로 검증하고 결과를 이 절에 덧붙인다.

**주 대상 — A. 출근길 직장인 (예: 민준, 32, IT 회사, 지하철 25분)**
- 지금: 포털 메인 · 유튜브 쇼츠 · 단톡방 링크로 뉴스를 접한다.
- 불편: ① 많이 클릭된 기사 ≠ 중요한 사건 ② 기사마다 들어가 읽을 시간이 없음 ③ 회의 · 점심 대화에서 이슈를 모르면 곤란 ④ 앱을 열고 로그인하는 것도 귀찮음 ⑤ (실측) 아침 7시에 열면 아직 전날 랭킹(예약 실행 지연 136~144분, O0에서 대응)
- JTBD: "아침 지하철에서 1분 안에, 오늘 대화에 필요한 이슈를 알고 싶다."

**보조 인사이트 — B. 취업 준비생** (운영자 본인의 실제 경험, 2026-10-17)
- 매일 전 영역 이슈를 정리하지 않는다. 다른 준비할 것이 많고, **면접이 잡혔을 때 그 기업의 뉴스를 몰아서 찾는다.**
- → 매일 보는 주 대상이 아님. 후보 기능 "기업 · 키워드로 지난 이슈 찾기"(쌓인 DB에서 검색, 검색마다 newsdata 크레딧을 쓰지 않게)는 백로그.

**후보 — C. 업종 이슈가 중요한 직장인**: 관심 키워드가 크게 보도된 날에만 알림 → 백로그(사용자 비례 비용이 생기는 첫 기능, 유료 후보).

**안티 퍼소나 — 실시간 속보를 원하는 사용자**: 데이터가 12시간 늦어 맞지 않는다.

확인 질문(인터뷰): 아침에 뉴스를 언제 · 어디서 · 무엇으로 보는가 / 가장 귀찮은 점 / 홈 화면 위젯을 쓰는가 / "많이 보도된 순" 랭킹이 쓸모 있는가 / 하루 중 다시 확인하는 때.

## 4. 로드맵 (운영 단계)

| 순서 | 기능 | 대상 불편 | 메모 |
|---|---|---|---|
| O0 (완료 10-17) | 하루 실행 04:17 KST | A ⑤ | cron `17 19 * * *`(D3) |
| O1 | **홈 화면 위젯 1단계** | A ①~④ | 아래 규칙. SPEC US-11 |
| O2 | Google 로그인(카카오는 검토) | 가입 귀찮음 | Better Auth 소셜 로그인, 기존 이메일 계정과 연결 규칙 필요 |
| O3 | 인스타 "오늘의 이슈" 카드 | 사용자 확보 | 매일 카드 이미지 자동 생성 → 처음엔 수동 게시, 이후 자동 게시 검토 |
| O4 | PWA + 아침 푸시 · 공유 카드 | 다시 오게 하기 | SPEC "범위 밖: 알림/구독"을 그때 범위 안으로 옮김 |
| 백로그 | 네이티브 위젯 앱, 이슈 타임라인("3일째 상위"), 기업 · 키워드 검색, 키워드 알림, 주간 정리 | | 사용자 반응을 본 뒤 |

**O1 위젯 규칙(사용자 결정 2026-10-17, PLAN.md D22)**
- 표시: 연관기사 수는 보이지 않고 **제목만** 뉴스 헤드라인처럼. 하단에 데이터 갱신 시각.
- 순서: **섹션별 1위**(연관기사 많은 순) → 남은 이슈를 **연관기사 순**(동점은 D16). 위젯 크기에 들어가는 만큼만(작은 위젯 약 3줄 · 중간 약 5줄 · 큰 위젯 약 10줄).
- 누르면: **이슈랭크 사이트의 그 이슈 상세**(3줄 요약 · 연관기사 수 · 원문 링크)가 열림 → 사이트에 이슈 바로가기 링크 추가.
- 서버: 위젯 전용 공개 API 한 곳에서 순서를 정해 내려주고(두 플랫폼이 같은 규칙), 위젯은 받은 목록을 그리기만 한다.
- 플랫폼: iPhone(Scriptable 스크립트) · Android(위젯 앱 무료 범위 조사 후 위젯 앱 또는 간단한 네이티브 위젯) 둘 다. 스크롤 없는 고정 화면(iOS 위젯 제약).

## 6. 수익화 방향 · 비용 · 약관

**비용 현황(2026-10-17 실측 · 확인)**
- DB 12MB(기사 767행 약 0.9MB), 하루 약 0.3MB · 1년 약 100MB → Supabase 무료 500MB 안에서 수년.
- newsdata 무료: 하루 200크레딧, 12시간 지연. 상업 이용은 사용자가 확인(가능) · newsdata 자료 다수가 가능으로 표기, 다만 같은 회사 비교표 하나는 불가로 표기 → 운영 전 공식 약관을 캡처해 둔다. 지연 없는 유료 플랜은 월 약 200달러부터(newsdata 블로그 기준, 변동 가능).
- OpenAI(gpt-6-luna): 하루 정리 약 0.006달러 + 요약.
- Vercel Hobby: **비상업 전용** → 수익을 내는 시점에 Pro 전환 필요.

**원칙**: 지금 비용은 "하루 1회 수집"에 비례해 사용자 수와 거의 무관하다. 사용자별로 외부 호출이 생기는 기능(키워드 알림 · 실시간 검색)이 사용자 비례 비용의 시작이므로 유료 기능 후보로 둔다.

**모델 후보(순서)**: 후원 → 프리미엄(키워드 알림 · 아카이브 검색 · 광고 제거) → 교육 · 기업용 주간 리포트 → 광고(트래픽이 커진 뒤).

**운영 기본(로드맵과 별개로 필요)**: 가입을 받으므로 **개인정보처리방침 · 이용약관 · 문의처** 페이지, 뉴스 콘텐츠(제목 · 설명문 · AI 요약)의 이용 범위 검토, Supabase 백업 방법 확인. 수익화 전에 반드시 끝낸다.
