# PLAN_ops_O4_pwa_share — PWA(홈 화면 앱) + 카카오톡 공유

> 이유: 출근길 사용자(PRODUCT_PLAN 2절 A)는 매일 브라우저에서 주소를 다시 찾아야 하고(불편 ④), 본 이슈를 친구에게 줄 때는 기사 링크만 보낸다(3절 여정 "수시: 친구와 공유"). 지금 사이트에는 manifest · 아이콘 · OG 태그가 하나도 없다(`index.html` head = charset · viewport · title · 글꼴 CSS뿐) → 홈 화면에 앱으로 둘 수 없고, 카카오톡에 붙인 링크 미리보기에도 설명 · 그림이 없다. 그래서 manifest · 아이콘 · 서비스 워커로 설치되는 웹 앱(PWA)을 만들고, 상세창 · 카드 · 맨 아래 줄에 "공유"(휴대폰 공유 창 → 카카오톡, 그 밖은 링크 복사)와 사이트 공통 OG 미리보기를 더한다. 아침 푸시는 이번에 넣지 않는다(D29, O5 후보).
> 코드 폴더: `ex12/` (운영 폴더, 복사 없음 — PLAN.md D21). 보고: `reports/ops_O4_pwa_share_build.md` · `reports/ops_O4_pwa_share_judge.md`.
> SPEC 근거: **US-13 · AC-13-1~4**(운영 O4, PLAN.md D29 — 2026-10-19 SPEC.md 반영). 회귀: AC-04-2 · AC-05-2 · AC-06-3 · AC-07-3 · AC-09-2 · AC-11-2 · 범위 밖 "알림/구독" · "기사 본문 전체 재게시". 적용 결정: D10(프로덕션 주소 하나) · D21 · D22 · D23(Android 위젯은 2단계 그대로, 1단계 바로가기 안내를 앱 설치로) · D24(Web Analytics, 사용자 지정 이벤트 없음) · D26 · D28(제목 재게시 원칙). **D29**(PWA · 공유 규칙, 확정 — 사용자 2026-10-19, 아래 "결정" Q1~Q11).

## 이번 범위
- PWA: `public/manifest.webmanifest` · 아이콘 PNG 5개 + OG 그림 1개(`tools/pwa-images.tsx`로 한 번 그려 저장소에 둠) · `public/sw.js`(오프라인 안내 1개만 저장) · `public/offline.html` · `index.html` · `widget.html` head 태그 · 설치 버튼. 공유: `index.html` 상세창 · 목록/북마크 카드 · 맨 아래 줄 "공유"(Web Share → 없으면 링크 복사) · 사이트 공통 OG. `widget.html`: Android 바로가기 안내 → 앱 설치 안내 + iPhone "홈 화면에 추가". `next.config.mjs`: rewrite 2 · headers 2.
- 새 패키지: **없음** — 그림은 Next 16.4에 든 `next/og` ImageResponse(O3와 같음), Web Share · 클립보드 · 서비스 워커는 브라우저 API, Kakao SDK 없음(D29).
- 확정(D29, 사용자 2026-10-19): ① 공유 = 휴대폰 공유 창 + 그 밖은 링크 복사, Kakao SDK 없음 ② 미리보기 = 사이트 공통 정적 OG ③ 보내는 글에 요약 없음 ④ 버튼 = 상세창 · 목록/북마크 카드 · 맨 아래 `이슈랭크 공유`(헤더 없음) ⑤ 오프라인 = 안내 화면만 ⑥ 설치 유도 = 헤더 아이콘 + 맨 아래 `앱 설치`(메인 → `/widget` 첫 링크, O1의 "링크 안 함"을 이번에 바꿈) ⑦ `/widget` Android 안내 → 앱 설치 + iPhone 절 ⑧ 측정 = 경로 `/app` · `/s` ⑨ 아이콘 = 검은 바탕 흰 마크 ⑩ 아침 푸시 = 이번 범위 밖(O5 후보).
- 하지 않음: 아침 푸시 · 알림 · 구독(O5 후보) · Kakao SDK · 이슈별 OG 주소 `/s/<id>` · 이슈 그림 카드(다음 후보) · O3 카드 파일 공유 · 오프라인 랭킹 보기 · manifest `shortcuts` · `share_target` · 배지 · 설치 화면 스크린샷 · iOS 시작 화면 그림 · 옛 `apple-mobile-web-app-*` meta · TWA · Play 스토어 · 네이티브 앱(D23 2단계 위젯 앱과 별개) · 위젯(`/api/widget` · `widget.js`) · 로그인(`auth.ts`) · 카드(`/api/card*` · `card.html`) · 하루 실행 · AI · 수집 · 묶기 · 요약 · `daily.yml` · DB 스키마 · API 계약(`openapi.yaml`) · 정책 문안(고칠 것 없음 — 아래 "개인정보 · 측정") · 새 npm 패키지 · `web/`.

## SPEC (SPEC.md US-13 · AC-13-1~4와 같음 — PLAN.md D29)
- **US-13 (앱 설치 · 공유, 운영 O4)** — 출근길 사용자로서, 이슈랭크를 홈 화면 앱으로 두고 본 이슈를 카카오톡 등으로 친구에게 바로 보내고 싶다. 그래야 매일 주소를 찾지 않고 열고, 대화에서 같은 이슈를 쉽게 나눌 수 있다.
- **AC-13-1** — Given 설치를 지원하는 브라우저로 사이트를 열었을 때, When 앱을 설치하면, Then 이슈랭크 이름 · 아이콘으로 홈 화면에 생기고, 열면 주소창 없는 창에 최근 랭킹이 보인다.
- **AC-13-2** — Given 사이트를 연 적 있는 기기가 인터넷에 연결되지 않았을 때, When 이슈랭크를 열면, Then 오프라인 안내와 다시 시도 버튼이 보이고, 랭킹 · 북마크 · 로그인 응답은 기기 캐시에 저장되지 않는다.
- **AC-13-3** — Given 이슈 상세나 카드를 보고 있을 때, When 공유를 누르면, Then 휴대폰은 공유 창, 그 밖은 링크 복사로 그 이슈의 제목 · 섹션과 그 이슈로 바로 가는 주소가 전달되고, 받은 사람이 주소를 열면 그 이슈 상세가 열린다. 본문 · 요약 · 연관기사 수는 보내지 않는다.
- **AC-13-4** — Given 이슈랭크 주소를 카카오톡 등에 붙였을 때, When 미리보기가 만들어지면, Then 사이트 이름 · 설명 · 대표 그림이 보인다.
