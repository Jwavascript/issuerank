# PLAN_ops_O2_google_login — Google 로그인

> 이유: 출근길 사용자는 사이트를 열고 로그인하는 것도 귀찮아한다(PRODUCT_PLAN 2절 A 불편 ④). 지금은 북마크를 쓰려면 이름 · 이메일 · 8자 이상 비밀번호로 가입해야 한다. 그래서 설치된 Better Auth 1.7.7의 Google 소셜 로그인을 켜서, 로그인 창의 "Google로 계속하기"를 한 번 누르면 가입 · 로그인되게 한다. 같은 이메일로 가입한 기존 이메일 계정과는 자동으로 잇지 않고 안내만 한다(메일 인증 없는 가입이라 선점 탈취 위험이 있음). Google 앱을 누구나 쓰도록 게시하려면 개인정보처리방침 · 이용약관 주소가 있어야 하므로(Google 공식) 최소 페이지도 함께 만든다(⑤).
> 코드 폴더: `ex12/`(운영 폴더, 복사 없음 — PLAN.md D21). 보고: `reports/ops_O2_google_login_build.md` · `reports/ops_O2_google_login_judge.md`.
> SPEC 근거: US-06 · AC-06-3 · AC-06-4(운영 O2, D26) · AC-06-1 · AC-06-2(이메일 흐름 회귀). 회귀: AC-07-3 · AC-08-3 · AC-11-2 · US-07 · 08 · 10. 적용 결정(모두 확정): D9(이메일 · 비밀번호 로그인 유지, 보류했던 소셜은 O2에서 Google 추가) · D10(프로덕션 주소 하나 · 프리뷰 로그인 미지원 · 같은 프로세스 BFF) · D21 · D24 · **D26**(Google 로그인 규칙, 사용자 2026-10-17 — 아래 ①~⑨).

## 이번 범위
- 서버: `server/auth.ts`(Google provider · 상태 쿠키 · 계정 연결 · 토큰 · 닫는 경로 규칙) · `.env.example`(이름 2개) · `openapi.yaml`(경로 2개). 화면: `public/index.html` 로그인 창의 "Google로 계속하기"와 돌아온 뒤 처리. 정책 페이지 `public/privacy.html` · `public/terms.html`(초안 · 문의처 자리표시자) + `next.config.mjs` rewrite 2줄(⑤), 640px 이하 로그아웃 버튼(⑨).
- 새 패키지: 없음(better-auth 1.7.7에 Google provider가 들어 있고, 이것이 쓰는 jose · @better-fetch는 이미 lockfile에 있음). DB 스키마 · 마이그레이션: 없음(0005의 `account`에 `provider_id` · `account_id` · 토큰 칸 · `scope`가 이미 있고, `user.email`은 unique).
- 확정(D26, 사용자 2026-10-17): ① 같은 이메일의 기존 계정이 있으면 잇지 않고 안내 ② Google이 미인증이라고 한 이메일은 새 가입만 허용 · 연결 안 함 ③ Google 토큰은 저장하지 않음 ④ Google 가입자에게 비밀번호를 붙이는 기능 없음 ⑤ `/privacy` · `/terms` 최소 페이지를 O2에 포함(초안 → Google 앱 게시 전 사용자 확인, 법률 검토 권장) ⑥ 탈퇴는 문의 이메일로 요청받아 운영자가 그 사용자 행만 삭제(실행할 때 승인). 문의 이메일은 사용자가 새로 만들어 알려 주며, 그 전까지는 자리표시자 ⑦ 이메일 인증 · 비밀번호 재설정 메일은 계속 범위 밖 ⑧ 카카오는 나중 후보 ⑨ 휴대폰 로그아웃 버튼 추가. 푸시는 O1 17번(10-18 05~09시) 확인 뒤, Vercel 환경 변수는 사용자가 푸시 전에 넣음.
- 하지 않음: 카카오 · 네이버 등 다른 제공자 · 로그인한 상태에서 Google 계정 직접 연결(`/link-social`) · 비밀번호 설정 · 이메일 인증/재설정 메일(SMTP 없음) · 탈퇴 버튼 · One Tap/ID 토큰 로그인 · Google API 추가 범위 · 브랜드 인증(로고 · 앱 이름 표시) · 인앱 브라우저 안내 문구(문제가 확인되면 O3) · 푸시(O4) · 인스타(O3) · 위젯(`/api/widget` · `widget.js` · `widget.html`) · 하루 실행 · AI · 북마크 · 폴더 API · `server/bff.ts` · 라우트 · `web/`.

## Google 로그인 규칙
| 항목 | 규칙 |
|---|---|
| 켜는 조건 | `GOOGLE_CLIENT_ID` · `GOOGLE_CLIENT_SECRET`(Better Auth 문서의 이름)이 둘 다 비어 있지 않을 때만 `socialProviders.google`을 켠다. 하나라도 비면 끈다 → `POST /api/auth/sign-in/social`은 404 `PROVIDER_NOT_FOUND`, 이메일 로그인 · 랭킹 · 위젯은 그대로(앱 준비 실패로 만들지 않음 — 그렇게 하면 `/api` 전체가 502가 됨). 값은 `ex12/.env`와 Vercel Production에만 둔다(ID = Config · SECRET = Secret, 바꾸면 Redeploy) |
| 시작 | 화면 → `POST /api/auth/sign-in/social` JSON `{"provider":"google","callbackURL":돌아올 주소,"errorCallbackURL":같은 주소}`(다른 칸은 보내지 않음) → 200 `{"url","redirect":true}` + 상태 쿠키 1개 + `Cache-Control: no-store`(라이브러리가 200 응답에도 `Location` 헤더를 붙이지만 fetch는 따라가지 않음). 화면은 `url`이 `https://accounts.google.com/`로 시작할 때만 `location.assign`. 돌아올 주소가 `/`로 시작하는 상대 주소도 아니고 같은 origin도 아니면 403 `INVALID_CALLBACK_URL` · `INVALID_ERROR_CALLBACK_URL`(라이브러리) |
| Google 주소 | `https://accounts.google.com/o/oauth2/v2/auth` + `response_type=code` · `client_id` · `redirect_uri` · `scope=openid email profile`(`disableDefaultScope: true` + `scope` 3개로 고정: Google 문서 순서, 라이브러리 기본 `email profile openid`와 내용은 같음, 모두 비민감 범위이고 추가 없음) · `state`(32자) · `code_challenge`(43자) + `code_challenge_method=S256`(PKCE, Google provider에서는 필수) · `include_granted_scopes=true`(기본). `access_type` · `prompt` · `login_hint` · `nonce`는 없음 → refresh token을 받지 않음. `redirect_uri` = `{BETTER_AUTH_URL}/api/auth/callback/google` → 배포 `https://issuerank-kappa.vercel.app/api/auth/callback/google` · 로컬 `http://localhost:3000/api/auth/callback/google`(Google 클라이언트에는 이 두 주소만 등록) |
| 상태 쿠키 | `account.storeStateStrategy: "cookie"`: state · code_verifier(128자) · 돌아올 주소 · 만료(10분)를 secret에서 만든 키로 암호화해 `better-auth.oauth_state` 쿠키 하나에 담는다(배포는 `__Secure-` 접두 · Secure, HttpOnly · SameSite=Lax · Path=/ · Max-Age=600). 시작 · 취소 · 상태 실패에서 DB 쓰기 0(기본값인 `database` 방식은 시작할 때마다 verification 행을 쓰고 5분짜리 쿠키를 쓴다 → 끝내지 않은 시작이 행으로 남고, 로컬 검증이 공유 DB에 쓰게 됨). 콜백의 `state`가 쿠키 안의 값과 다르면 거절하고, 끝나면 쿠키를 만료시킴 |
| 콜백 | Google → `GET /api/auth/callback/google?state&code`(같은 프로세스 BFF를 그대로 지남) → `POST https://oauth2.googleapis.com/token`(code · code_verifier · client secret) → 토큰 응답의 ID 토큰에서 `sub` · `email` · `email_verified` · `name`을 읽음(1.7.7 Google provider는 userinfo를 부르지 않음 — 코드 확인) → 아래 계정 규칙 → 성공이면 302 `Location` = callbackURL · `Set-Cookie` 세션(`better-auth.session_token`, 이메일 로그인과 같은 속성 · 7일) + 상태 쿠키 만료 / 실패면 302 `Location` = errorCallbackURL 뒤에 `error={코드}`(해시보다 앞에 붙음). 상태를 읽지 못하면(쿠키 없음 · 깨짐) `onAPIError.errorURL: "/"`에 따라 `/?error=state_mismatch`(기본 `/api/auth/error` 페이지는 쓰지 않음). 모두 no-store |
| 저장 칸 | user: `name` = Google `name`에서 앞뒤 공백을 뺀 값, 비면 이메일의 `@` 앞부분(Google은 name을 꼭 주지는 않음) · `email`은 소문자 · `email_verified`는 Google 값 · `image` = null(`mapProfileToUser`로 처리, 쓰지 않는 사진 주소는 저장하지 않음). account: `provider_id` = `google` · `account_id` = `sub`(Google이 권하는 고유 키) · `password` null · `scope`는 라이브러리 값 · `access_token` · `refresh_token` · `id_token` · 만료 시각 2개 = null(③: `databaseHooks.account.create.before`로 비우고 `account.updateAccountOnSignIn: false`). session: 지금과 같음(IP · user agent 칸 포함) |
| 닫는 경로 | `disabledPaths`: `/link-social` · `/unlink-account` · `/get-access-token` · `/refresh-token` · `/account-info` → 404(화면에서 쓰지 않고, ①과 ③을 API로 우회하지 못하게 함). Google `disableIdTokenSignIn: true` → 본문의 `idToken`으로 로그인하면 404 `ID_TOKEN_NOT_SUPPORTED`. `trustedProviders`는 두지 않음 |
| 보안 그대로 | `trustedOrigins` = BETTER_AUTH_URL origin 하나. CSRF · Origin 검사 유지(쿠키가 있는 POST가 다른 Origin이면 403). 쿠키 없는 시작 POST는 라이브러리가 Origin을 보지 않는다. 대신 그 결과는 상태 쿠키를 가진 브라우저에서만 끝까지 가고, JSON 본문만 받는다(기록만 함). 프리뷰 · 고유 배포 주소의 로그인 미지원은 그대로(D10, redirect URI가 프로덕션 하나뿐) |
| 로그 · 속도 | 로거 그대로: 라이브러리의 error 로그는 `AUTH_INTERNAL_ERROR` 한 줄씩(취소는 0줄, 상태 실패 · 코드 교환 실패 · `account_not_linked`는 1줄). 원문 · 토큰 · client secret · 이메일 출력 0. 예기치 못한 예외는 기존 onError 500 · `API_INTERNAL_ERROR`. 속도 제한은 라이브러리 기본(production · `next start`에서만): `/sign-in*` · `/sign-up*` 경로마다 10초에 3번 → 넘으면 429 |
| BFF · 계약 | `server/bff.ts` · `app/api/[...path]/route.ts`는 고치지 않음(302 · `Location` · 여러 `Set-Cookie` · no-store가 그대로 가는지는 테스트로 확인). `openapi.yaml`에 `POST /api/auth/sign-in/social`(요청 3칸 · 200 · 403 · 404)과 `GET /api/auth/callback/google`(302 · `Location` · `Set-Cookie` · error 코드)을 더하고 info.version 0.3.0 |

### 계정 규칙 (①②④ 확정 — D26)
| 경우 | 동작 | 화면 |
|---|---|---|
| 처음 보는 Google 계정 · 같은 이메일 계정 없음 | 가입(user + account `google`) · 로그인 | 토스트 "로그인했습니다" |
| 같은 Google 계정(`sub`)으로 다시 | 그 계정으로 로그인 · 새 행 0. Google 쪽 이름 · 이메일이 바뀌어도 저장값은 그대로(`overrideUserInfoOnSignIn` 기본 false) | 같음 |
| 같은 이메일의 이메일 · 비밀번호 계정이 있음 | 잇지 않음(`account.accountLinking.disableImplicitLinking: true`) → `error=account_not_linked` · 새 행 0 · 기존 계정과 북마크 그대로 | "이미 가입된 이메일입니다. 처음 가입한 방법으로 로그인해 주세요" |
| Google이 `email_verified` false라고 함 | 같은 이메일 계정이 없으면 가입 허용(user `email_verified` false — 이메일 가입도 인증 없이 받으므로 같은 수준). 같은 이메일 계정이 있으면 위처럼 거절 | — |
| Google 가입자가 이메일 · 비밀번호로 | 비밀번호(credential 행)가 없음 → 로그인 401 · 가입 422 | 기존 "이메일 또는 비밀번호를 확인해 주세요" · "이미 가입된 이메일입니다" |
- 이유: 이메일 가입에는 메일 인증이 없어서(D9, 모든 계정이 `email_verified` false) 가입한 사람이 그 주소의 주인이 아닐 수 있다. 자동으로 이으면 남의 주소로 먼저 가입해 둔 사람이 비밀번호로 계속 들어올 수 있다(선점 탈취). 1.7.7은 기본으로도 로컬 미인증 계정과의 연결을 막는다(`requireLocalEmailVerified` 기본 true · 폐지 예정, 설치된 코드 `oauth2/link-account.mjs`에서 확인 — 문서에는 없음). 그래도 이 기본값에 기대지 않고, 문서에 있는 `disableImplicitLinking`으로 고정한다. `trustedProviders`에 google을 넣으면 Google이 미인증이라고 한 이메일까지 잇는 쪽으로 넓어지므로 넣지 않는다(문서의 "account takeover" 경고).
- 나중 후보: 이메일로 로그인한 상태에서 "Google 계정 연결"(`/link-social` — 세션 · 같은 이메일 · Google 인증 이메일을 모두 확인하므로 안전) · Google 가입자의 비밀번호 설정(`setPassword`는 서버 전용이고, 문서는 재설정 메일을 권함 → SMTP 필요).

### 사용자 할 일 (구현 순서대로 — 값은 채팅 · 문서 · 로그에 남기지 않음)
푸시 전(제작과 함께 해도 됨, 로컬 검증은 가짜 값으로 함):
1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 새 프로젝트를 만든다(예 `issuerank`).
2. 메뉴 › Google Auth Platform › 시작하기: 앱 이름 `이슈랭크` · 사용자 지원 이메일 · 대상 **외부(External)** · 연락처 이메일을 넣고, Google API 서비스 사용자 데이터 정책에 동의 → 만들기. 사용자 지원 이메일은 동의 화면에서 사용자에게 보인다(Google 문서) → 고를 수 있으면 새 문의용 주소를 고른다(본인 계정 · 관리하는 그룹 주소만 고를 수 있는지는 확인 필요).
3. 데이터 액세스: 범위는 `openid` · `.../auth/userinfo.email` · `.../auth/userinfo.profile`만(로그인 기본 범위이고 비민감 → 앱 검증이 필요 없음).
4. 클라이언트 › 클라이언트 만들기 › **웹 애플리케이션**: 승인된 리디렉션 URI에 `https://issuerank-kappa.vercel.app/api/auth/callback/google`(로컬에서도 해 볼 때만 `http://localhost:3000/api/auth/callback/google`도), JavaScript 원본은 비워 둠 → 만들기. 클라이언트 보안 비밀번호는 **만들 때 한 번만** 전체가 보이고 내려받을 수 있다(그 뒤에는 끝 4자만 보이고, 잃어버리면 새 비밀을 추가). 설정이 반영되기까지 5분~몇 시간 걸림.
5. 대상: 게시 상태는 **테스트**로 두고, 테스트 사용자에 본인 Gmail을 넣는다(최대 100명, 기본 프로필 범위라 7일 만료 없음). 게시는 11번에서만 한다.
6. Vercel › 프로젝트 › Settings › Environment Variables › Production에 `GOOGLE_CLIENT_ID`(Config) · `GOOGLE_CLIENT_SECRET`(Secret)을 **푸시 전에** 넣는다(푸시로 생기는 새 배포가 바로 읽으므로 따로 Redeploy할 필요 없음, 푸시 뒤에 바꾸면 Redeploy). (선택) `ex12/.env`에도 같은 두 이름(로컬과 배포는 같은 DB를 쓰므로 로컬에서 로그인해도 실제 계정이 생김).

### 카카오 (⑧ 확정 — 이번에는 빼고 나중 후보)
- 필요한 것: Kakao Developers 앱 · 카카오 로그인 사용 ON · Redirect URI(`…/api/auth/callback/kakao`) · 동의항목 · REST API 키 + 클라이언트 시크릿([설정하기](https://developers.kakao.com/docs/latest/ko/kakaologin/prerequisite)). 이메일(`account_email`) 동의항목은 "비즈 앱, 테스트 앱"만 설정할 수 있다([동의항목](https://developers.kakao.com/docs/latest/ko/kakaologin/utilize#scope-user)). 사업자등록번호가 없는 개인도 앱 오너 본인인증 + 카카오비즈니스 통합 서비스 약관 동의로 비즈 앱 전환이 가능하다([개인 개발자 비즈 앱](https://developers.kakao.com/docs/latest/ko/app-setting/app#biz-app-for-individual)). 일부 추가 기능 신청은 심사가 영업일 3~5일. Better Auth 1.7.7에 kakao provider가 있고(기본 범위 `account_email` · `profile_image` · `profile_nickname`), Better Auth는 모든 사용자에게 이메일이 필요하다([OAuth 문서](https://www.better-auth.com/docs/concepts/oauth)) → 비즈 앱으로 전환하지 않으면 가입이 `email_not_found`로 실패.
- 결정(D26): O2에서 빼고 나중 후보로 남긴다. 국내 사용자에게 익숙하다는 장점은 크지만(공식 수치 없음 — 확인 필요), 별도 앱 · 본인인증 · 동의항목 · 처리방침 항목이 더 필요하다. Google로 연결 규칙 · 정책 페이지 · 운영 흐름을 먼저 확인하고, 가입 수와 요청을 본 뒤 정한다.

## 화면 변경
- 로그인 창(`#authDialog`) 제목 바로 아래: "Google로 계속하기" 버튼(Google 버튼 지침: 표준 4색 G 로고를 크기 · 색 그대로, 바탕 #FFFFFF · 테두리 #747775 · 글자 #1F1F1F, 창 너비 가득) → 작은 구분 글 "또는 이메일로" → 기존 이름 · 이메일 · 비밀번호 칸 · `#authError` · 버튼(로그인 · 회원가입 · 닫기)은 그대로. 로그인 · 회원가입 두 모드 모두 같은 버튼 · 같은 문구, 첫 초점(이메일 칸)도 그대로. 창이 지금처럼 늘 밝은 색이므로 버튼도 밝은 꼴 하나만.
- 누르면: 기존 `authBusy`처럼 창의 버튼을 모두 잠그고 시작 요청을 보낸다 → 성공이면 잠근 채 Google로 이동, 실패면 `#authError`에 아래 문구를 띄우고 잠금을 푼다. Google 화면에서 브라우저 뒤로가기로 돌아와 페이지가 그대로 복원되면(bfcache `pageshow` persisted) 잠금을 푼다.
- 돌아올 주소(callbackURL = errorCallbackURL): `/?login=google` + (비로그인 북마크 안내 토스트의 "로그인"으로 연 창이면 `&issue={그 북마크 버튼의 이슈 id}`) + 지금 해시(`#list` · `#bookmarks` 등, 없으면 붙이지 않음). 그래서 북마크하려다 로그인한 사람은 돌아와서 그 이슈 상세창(기존 `?issue=` 바로가기)에서 바로 북마크를 누를 수 있다. 날짜는 바로가기 이슈의 날짜, 바로가기가 없으면 지금처럼 최근 수집일.
- 첫 로드: `issue` · `login` · `error` 중 하나라도 있으면 읽은 즉시 쿼리 전체를 지운다(해시와 기록 수는 그대로 — 기존 바로가기 방식). 순서: 랭킹 · 세션 확인 · 화면 그리기 → `issue` 처리(지금 그대로) → 로그인 상태 + `login=google` + `error` 없음이면 토스트 "로그인했습니다" / 비로그인 + `error`가 있으면 로그인 창(로그인 모드)을 열고 `#authError`에 문구 / 그 밖에는 아무것도 하지 않음. `error` 값 자체는 화면에 쓰지 않는다.

| 때 | `#authError` 문구 |
|---|---|
| 시작 404 `PROVIDER_NOT_FOUND` | 지금은 Google 로그인을 사용할 수 없습니다 |
| 시작 429 | 잠시 후 다시 시도해 주세요 (기존) |
| 시작 그 밖 · 네트워크 · `url`이 Google 주소 아님 | 인증 요청을 처리하지 못했습니다. 다시 시도해 주세요 (기존) |
| 돌아옴 `error=access_denied`(Google에서 취소) | Google 로그인을 취소했습니다 |
| 돌아옴 `error=account_not_linked` | 이미 가입된 이메일입니다. 처음 가입한 방법으로 로그인해 주세요 |
| 돌아옴 그 밖의 `error` | Google 로그인을 완료하지 못했습니다. 다시 시도해 주세요 |
- 그대로 두는 것: 이메일 가입 · 로그인 흐름과 문구(`authMessage`) · 비로그인 북마크 안내 · 북마크 탭 · 401 안내(모두 같은 로그인 창이라 Google 버튼이 함께 보임) · 북마크 · 폴더 · 이슈맵 · 목록 · 위젯 바로가기. 새 문구는 위 버튼 · 구분 글 · 표의 새 문구 4개뿐(⑤ · ⑨ 문구는 따로).
- 정책 링크(⑤): 로그인 창 맨 아래 "이용약관 · 개인정보처리방침"(새 탭), 메인 화면 맨 아래 모든 화면 공통 한 줄 "개인정보처리방침 · 이용약관 · 문의"(문의 → `/privacy#contact`, 메인 화면에는 이메일 주소를 쓰지 않음). 휴대폰 로그아웃(⑨): 640px 이하에서 로그인한 상태면 북마크 화면 제목 아래에 "{이름} · 로그아웃"(누르면 기존 `signOut`). 641px 이상은 기존 헤더 버튼 그대로.
