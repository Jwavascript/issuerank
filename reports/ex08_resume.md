# ex08 재개 — 실행 환경과 결정안 (2026-10-13)

최초 작성은 환경 복원과 결정안 검토 기록이다. **2026-10-13 후속 사용자 결정:** 동점 순위 1번 진행, AI 공급자는 OpenAI API로 전환. 현재 구현·검증 결과는 ex08_build.md와 ex08_judge.md의 2026-10-13 절을 따른다. 아래 Haiku 유지 제안은 채택하지 않은 과거 검토안이다. 실제 DB 적용은 미실행.

## 실행 환경 검증 결과

- Termux: Node.js 24.18.0 · npm 11.20.0 설치. Node 직접 실행으로 기존 테스트 6파일 51개 통과.
- Android 직접 빌드: Turbopack 네이티브 바인딩 없음. Webpack 재시도도 TypeScript 7의 `@typescript/typescript-android-arm64` 부재로 실패. 제품 결함과 구분한다.
- 기존 proot Ubuntu에 공식 Node.js 24.18.0 Linux ARM64 설치(SHASUMS256.txt 대조 성공), 동봉 npm 11.16.0. Linux에서 `npm ci --no-audit --no-fund` 성공(88패키지).
- 저장소 루트에서 `bash scripts/ex08-ubuntu.sh npm test`: **6파일 51개 통과**.
- 같은 래퍼로 `npm run build`: **Next.js 16.4.0 Turbopack 빌드 + tsc --noEmit 성공**, 종료 코드 0.
- Vite 설정의 향후 native loader 호환 경고와 esbuild 설치 스크립트 승인 안내가 있었지만 이번 테스트·빌드는 성공했다. 패키지 버전·lockfile·제품 코드는 변경하지 않았다.
- `.env` 없음: 실제 DB 연결·마이그레이션·뉴스 수집·AI 응답 비교·DB 화면 통합 검증은 미실행. 전체 ex08 심사를 PASS로 바꾸지 않았다. 이번 실행 결과는 이전 심사 FAIL을 해소한 것이 아니다.
- 시작한 상주 서버 없음. 커밋·푸시 없음.

[Next.js 공식 문서](https://nextjs.org/docs/app/api-reference/turbopack#supported-platforms)의 플랫폼 안내와 실제 설치 오류를 확인하고 Linux 실행 환경을 사용했다. 기동 방법은 HANDOFF.md 참고.

## 동점 순위 결정안

추천: 연관기사 수 ↓ → AI 중요도 ↓ → 최신 발행 시각 ↓ → id 자연 순서.

- `issues.importance` 정수 NOT NULL DEFAULT 0을 0004 마이그레이션으로 추가. 기존 행·규칙 경로·AI 응답에서 빠진 기사는 0, AI가 분류한 이슈는 현재 검사에서 보정한 1~5를 저장한다. 과거 점수를 추정해 채우지 않는다.
- `grouping.ts`에서 저장 행으로 중요도를 넘기고 `db/store.ts`의 삽입·충돌 갱신에 반영한다. 북마크 때문에 건너뛴 섹션은 그대로 보존한다.
- `rankIssues`를 사용하는 화면·북마크 카드·요약 Top 5가 같은 순서를 따르도록 `IssueRow`, `SummaryIssue`, 요약용 DB 조회에도 연결한다. 화면 API 응답 칸은 유지한다.
- SPEC AC-03-2, PLAN.md, ex08 PLAN과 테스트를 함께 수정한다. 과거 ex01~ex07은 수정하지 않는다.
- 후보 선정은 묶음 크기 우선이고 최종 순위는 검색 후 연관기사 수 우선이다. 따라서 중요도를 추가해도 “첫 후보 = 최종 1위”를 보장할 수 없다. 심사는 저장된 모든 이슈를 최종 정렬 규칙으로 계산한 결과와 비교해야 한다.
- 회귀 검증: 건수 우선, 동점 중요도 우선, 같은 중요도면 시각·id 순서, 기존 중요도 0, AI 점수 저장·재묶기 갱신, 요약 Top 5와 화면 순위 일치.
- 대안: 기존 건수 → 시각 → id를 유지하고 ex08 심사 기대값만 수정. DB 변경 없이 기존 SPEC을 유지할 수 있다.

## AI 정리 품질 결정안

추천: D6 비용 최소화와 Haiku 4.5를 유지하며 `server/ai.ts`의 정리 지시문부터 보강한다.

- 같은 주제보다 같은 사건·발표·사고를 기준으로 합친다. 국채 매도·비축유 방출·인플레이션 전망은 경제 주제여도 별도 사건이라는 구체적인 분리 예시를 넣는다. 같은 사건인지 불명확하면 단독 묶음을 유지한다.
- 검색어 두 그룹은 한 사건의 대상·행위를 나타내는 짧은 핵심어로 정한다. 동의어는 같은 개념의 표현만 넣고 서로 다른 사건을 AND로 결합하지 않는다. 긴 구절은 고유명칭 등 필요한 경우에만 쓴다.
- excluded는 기존 제외 유형임을 입력에서 확인할 수 있을 때만 사용한다. 중요도가 낮거나 설명문이 짧다는 이유만으로 실제 사건을 제외하지 않는다.
- 수집 태그보다 사건 내용을 우선하여 섹션을 정하고, 중요도는 기사 개수와 구분한다.
- 검색 재시도는 추가 크레딧·D13 변경이 필요하므로 이번 첫 개선에는 넣지 않는 안이다. 모델 변경과 자동 재호출도 추가하지 않는다.
- 기존 mock 테스트 통과만으로 AI 품질 개선을 증명할 수 없다. 키 준비 후 동일한 저장 입력으로 제한된 전후 비교를 하며, 오묶음·같은 사건 분리·잘못된 제외·섹션 오분류·검색어 타당성을 직접 평가한다. 실제 검색 품질은 newsdata 호출 없이 확정하지 않는다.
- 기존 요약의 입력 밖 사실 문제는 별도로 남아 있다. 정리 프롬프트만 바꿔 해결됐다고 판정하지 않고 실제 DB 요약도 이번에 삭제하지 않는다.

참고: [Anthropic 프롬프트 지침](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)은 명확한 제약과 관련 예시 사용을 안내한다. 이번 제안의 효과는 별도 실측 대상이다.
