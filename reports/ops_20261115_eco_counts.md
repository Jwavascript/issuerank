# 2026-11-15 경제 연관기사 수 조사

사용자 제보: 오늘 경제 1~5위 연관기사 수가 모두 1건. 운영 데이터 읽기와 현재 코드 확인만 수행했다. 제품·시험 코드 수정, 운영 쓰기, daily 재실행, newsdata·OpenAI 추가 호출은 하지 않았다.

## 확인한 사실

- 운영 `GET /api/rankings` 1회(Node fetch): date `2026-11-15`, updatedAt `2026-11-15T04:42:30+09:00`, 경제 1~5위 `articleCount` 모두 1. 즉 Android만의 표시 문제는 아니다.
- 공개 GitHub API: daily 실행 `43633483070`은 workflow_dispatch, 생성 시각 04:41:48 KST, conclusion success. 이후 schedule 실행 `43655844149`도 success(생성 08:58:20 KST). 실행 성공 표시는 데이터 품질을 보장하지 않는다.
- 공개 이슈 [운영 경보 2026-11-15](https://github.com/Jwavascript/issuerank/issues/1)에 `ALL_ONES Top 5 전부 1건 섹션 eco`가 이미 기록돼 있다. health 실행 `43633848863`, daily `43633483070`을 가리킨다.
- 현재 `ex12/server/grouping.ts`는 검색어 제목 검색 결과의 첫 쪽에서 추가 낱말이 맞는 비율을 계산해 `max(round(totalResults × 비율), 묶음 기사 수)`로 정한다. 검색 결과 0건, 검증 통과 비율 0, 검색 생략·실패 등으로 묶음 크기 1이 유지될 수 있다.
- `ex12/server/ranking.ts`는 저장된 articleCount로 정렬·표시한다. 동점이면 importance → 발행 시각 → id 순서다. 1건을 화면에서 임의로 만들지 않는다.
- 경제 1위는 제목이 한미 성장률·빅테크 투자인데 요약은 인텔 주가 급락을 설명하는 불일치 정황도 관찰했다. 원자료 설명문 확인 전 원인은 단정하지 않는다.

## 사용자 실행 요약 확인 후 추가 사실

사용자가 오늘 group·summarize 실행 요약을 제공했다.

- AI 정리: 묶음 76 · 제외 19 · 빠진 기사 0. API 호출·형식 검증 성공이며 분류·묶음의 의미적 정확성까지 입증하는 수치는 아니다.
- AI 분류 후 섹션별 기사 수: pol 17 / **eco 5** / soc 31 / cul 14 / wor 35 / it 27. 합계 129. `eco 기사 5`는 collect 단계의 경제 수집 건수가 아니라 AI 분류 후 경제 묶음의 소속 기사 수다(`grouping.ts` sections 결과 조립).
- 경제 5개 모두 묶음 크기 1, 이슈도 정확히 5개. 따라서 경제는 다른 후보를 제치고 이 5개를 골라낸 결과가 아니라 **남은 모든 경제 이슈를 Top 5로 표시**한 상태다.
- 경제 검색어: `AI AND (성장률 OR 빅테크)`, `안양시 AND (위례과천선 OR 서울서부선)`, `증권사 AND 3분기`, `혜린 AND 타코집`, `Viyash AND 매출`. 모두 검색 후 수치 1, 검색 실패·생략 note 없음.
- 총 검색 35번 · 실패 0 · 종료 시점 남은 크레딧 93. 이는 당시 잔액이며 현재 잔액으로 취급하지 않는다. 검색은 경제 5개 + 나머지 5섹션 각 6개 = 35개와 일치한다. **경제 검색 실패·크레딧 소진은 원인에서 제외**한다.
- 요약 요청 28 · 성공 28 · 실패 0 · 설명문 없음 2, collect/group/summarize 종료 모두 0. 이전 OpenAI 키 만료 장애와 같은 호출 실패가 이번에 발생한 것은 아니다. 다만 성공 로그는 요약 내용의 정확성을 보증하지 않는다.

## 아직 확정하지 못한 것

로그에는 각 검색의 원래 `totalResults`, 첫 쪽 제목 목록, 관련성 통과 건수가 없다. 따라서 **검색 결과 자체가 적었는지, 1쪽 검사 비율이 낮아 1로 남았는지**는 구분할 수 없다. ‘공급 API에 해당 사건 기사가 정확히 1개 있다’고 해석하면 안 된다. 계산 결과의 최소값은 수집 묶음 크기 1이기 때문이다.

**collect 로그도 수령**: pol 28 / eco 18 / soc 25 / cul 24 / wor 28 / it 25, 합계 148건 · 6섹션 모두 ok · 요청 18회. 수집 실패는 없다. 경제 수집 18건과 AI 분류 후 경제 5건은 비교 기준이 다르다. AI는 섹션을 넘어 합치고 재분류하므로 **원래 경제 18개 중 정확히 13개가 제외됐다고 계산하면 안 된다**. 원래 경제 기사가 어느 이슈·섹션으로 연결됐고 어느 기사가 제외됐는지 원자료별로 확인해야 한다. 로컬 `ex12/.env`와 gh 명령은 여전히 없다. 이 자료 없이 ‘AI가 경제 기사를 잘못 분류했다’고 단정하지 않는다.

### 수집량 증가 질문에 대한 판단

현재 정보만으로 수집량 증가를 우선 처방하지 않는다. 더 많은 표본을 확보할 수는 있으나 검색어·관련성 검사·분류 문제를 해결한다는 근거는 없다. 1건 표시는 수집 묶음 크기와 추가 검색 검증의 결과이므로 수집 페이지를 늘린다고 자동으로 커지지 않는다. 현재 하루 수집은 top1+전체2 페이지, 요청18회이며 추가 페이지·호출 예산·AI 입력량 변경은 별도 계획으로 다룬다. 이번 조사에서는 설정을 바꾸거나 추가 호출하지 않았다.
